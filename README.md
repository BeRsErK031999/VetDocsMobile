# VetDocs Mobile

Мобильная база ветеринарных регламентов, чек-листов и шаблонов документов на Docusaurus 3, TypeScript и React.

## Команды

```bash
npm install
npm run start
npm run build
npm run build:search
npm run serve
npm run mobile:build
```

`npm run build:search` собирает production-версию сайта и создает локальный индекс Pagefind в `build/pagefind`.

Для финальной web/mobile-сборки используйте `npm run build:search`: эта команда сначала выполняет production-сборку Docusaurus, а затем добавляет офлайн-индекс поиска Pagefind в `build/pagefind`.

`npm run build` нужен только для обычной Docusaurus-сборки без индекса поиска. После этой команды папка `build/pagefind` не создается, поэтому поиск в готовом статическом артефакте будет недоступен до запуска `npm run build:search`.

## Офлайн-режим

VetDocs Mobile собирается как статический справочник без внешних ссылок, CDN, аналитики и удаленного поискового сервиса. Поиск работает через локальные файлы Pagefind из `build/pagefind`, поэтому финальный артефакт для упаковки должен быть получен командой `npm run build:search`.

## Android-сборка

Android-оболочка подключена через Capacitor и использует локальную папку `build` как web-артефакт. Сервер для запуска приложения не нужен.

Для подготовки Android-проекта выполните:

```bash
npm run mobile:build
```

Команда выполнит `npm run build:search`, создаст Docusaurus production build с локальным индексом Pagefind и синхронизирует результат в Android-проект через `npx cap sync android`.

Полезные команды:

```bash
npm run mobile:sync
npm run mobile:open
```

`npm run mobile:sync` повторно синхронизирует уже собранный `build` в Android-проект. `npm run mobile:open` открывает Android-проект в Android Studio.

## Проверки

```bash
npm run lint
npm run typecheck
npm run test
npm run build
```

`npm run test` запускает строгую проверку структуры документов через `scripts/validate-docs.mjs`. Запускайте эту команду после каждого переноса бумажного документа и перед сборкой APK.

Валидация проверяет рабочие markdown-документы внутри `docs`, кроме `docs/_templates`. Возможные ошибки:

- нет frontmatter в начале файла;
- отсутствует `title`, `description`, `category`, `tags` или `lastUpdated`;
- `title`, `description` или `category` пустые;
- `tags` не оформлен как YAML-список;
- документ лежит вне разрешенных разделов `reception`, `sterilization`, `anesthesia`, `emergency`, `medicines`, `templates`;
- документ не добавлен в `sidebars.ts`.

Сообщение ошибки показывает сломанный файл, проблемное поле и способ исправления. Это важно запускать до `npm run mobile:build`, потому что Android APK должен собираться только из документов, которые доступны в навигации и корректно попадают в офлайн-поиск.

## Структура документации

Документы находятся в `docs`:

- `reception` - прием пациентов
- `sterilization` - стерилизация
- `anesthesia` - анестезия
- `emergency` - экстренные случаи
- `medicines` - препараты
- `templates` - шаблоны документов

## Как добавить новый документ

1. Скопируйте структуру из `docs/_templates/document-template.md`.
2. Создайте новый `.md` файл в нужной папке внутри `docs`.
3. Заполните frontmatter: `title`, `description`, `category`, `tags`.
4. Добавьте документ в `sidebars.ts` в нужный раздел.
5. Проверьте сборку:

```bash
npm run build
```

## Как создать документ через CLI

Для ускорения переноса бумажных документов используйте генератор:

```bash
npm run docs:create -- --section reception --slug primary-exam --title "Первичный осмотр" --description "Порядок первичного осмотра пациента" --tags "прием,осмотр,пациент"
```

Команда создает markdown-файл в выбранном разделе, добавляет frontmatter (`title`, `description`, `category`, `tags`, `lastUpdated`), вставляет базовую структуру клинического документа без клинических рекомендаций и автоматически добавляет id документа в нужный раздел `sidebars.ts`.

После создания:

1. Перенесите в файл только утвержденный текст бумажного документа.
2. Проверьте, что документ появился в нужной секции `sidebars.ts`.
3. Запустите проверку:

```bash
npm run test
```

Если документ не добавлен в `sidebars.ts` или нарушает структуру frontmatter, `npm run test` покажет файл, проблему и способ исправления.

## Как переносить бумажные документы

Переносите только утвержденный текст клиники. Не добавляйте медицинские рекомендации от себя, не меняйте клинический смысл и отмечайте спорные места для проверки ответственным сотрудником.

### Как называть файлы

Используйте короткие английские имена в `kebab-case`: только строчные буквы, цифры и дефисы.

Хорошие примеры:

- `patient-intake.md`
- `preoperative-checklist.md`
- `instrument-processing.md`
- `discharge-summary.md`

Не используйте пробелы, кириллицу, даты в случайном формате и общие названия вроде `new.md` или `document.md`.

### Как выбирать раздел

Выбирайте папку по рабочему сценарию документа:

- `docs/reception` - прием пациента, регистрация, первичный осмотр, анамнез.
- `docs/sterilization` - обработка инструментов, подготовка стерильных наборов.
- `docs/anesthesia` - документы подготовки и контроля анестезиологического сценария.
- `docs/emergency` - экстренные алгоритмы и триаж.
- `docs/medicines` - карточки препаратов и справочные документы по назначениям.
- `docs/templates` - шаблоны выписок, памяток и документов для владельца.

Если документ подходит сразу к нескольким разделам, выберите основной сценарий использования, а остальные документы укажите в блоке "Связанные документы".

### Как оформлять заголовки

В каждом документе должен быть один заголовок `#`, совпадающий с названием документа. Основные блоки оформляйте через `##`, а вложенные части через `###`.

Для клинических документов используйте структуру из `docs/_templates/clinical-document-template.md`:

- Название документа
- Назначение
- Когда использовать
- Ответственный сотрудник
- Порядок действий
- Важные замечания
- Что записать в карту пациента
- Связанные документы
- Дата обновления
- Версия

Порядок действий оформляйте нумерованным списком. Замечания, поля карты пациента и связанные документы оформляйте маркированными списками.

### Как добавлять документ в sidebar

После создания файла добавьте его id в `sidebars.ts` в подходящую категорию. Id строится от пути внутри `docs` без расширения.

Пример: файл `docs/anesthesia/preoperative-checklist.md` подключается как:

```ts
items: ['anesthesia/preoperative-checklist']
```

Если добавляете новый документ в существующую категорию, расширьте массив `items`, не меняя остальные разделы без необходимости.

### Как проверять поиск

После добавления документа запустите:

```bash
npm run build:search
```

Pagefind индексирует только реальные документы из рабочих docs-разделов. Проверьте поиск по:

- названию документа;
- ключевым словам из исходного бумажного текста;
- тегам из frontmatter;
- словам, которые сотрудник клиники будет вводить на телефоне.

Если документ не находится, проверьте, что файл лежит в одном из рабочих разделов `docs/reception`, `docs/sterilization`, `docs/anesthesia`, `docs/emergency`, `docs/medicines` или `docs/templates`.

### Как собирать APK после добавления документов

После проверки текста, sidebar и поиска выполните:

```bash
npm run mobile:build
cd android
.\gradlew.bat assembleDebug
```

`npm run mobile:build` пересобирает Docusaurus, создает офлайн-индекс Pagefind и синхронизирует папку `build` в Android-проект через Capacitor. APK появится в `android/app/build/outputs/apk/debug/app-debug.apk`.
